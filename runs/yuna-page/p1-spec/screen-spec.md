# 화면 스펙 — yuna.page 공개 화면

> 근거: `docs/story-service.md`(유저스토리) · `docs/prd.md` · `docs/design.md`
> 범위: 공개 화면(소개 + 메시지 폼)까지. 관리자 요청함·상세(US-4·US-5)는 run-02.

## 목적
연아의 QR 명함을 받은 친구 부모님이, 연아 소개를 보고 **안심하고 연아 아빠에게 메시지를 남긴다.** 핵심 행동은 "메시지 보내기" 하나다.

## 연결 유저스토리
- **US-1** 친구 부모님이 명함과 연결된 페이지임을 알아보고 안심하고 연락한다.
- **US-2** 가입 없이 친구 이름과 메시지를 남겨 다시 만날 기회를 만든다.
- **US-3** 편한 회신 수단(휴대폰)으로 답을 받는다.
- (US-4·US-5 = 관리자 요청함·상세 → run-02)

## 화면 목록
| 화면 | 이름 | 키스크린 | 진입 | 주요 요소 |
|---|---|---|---|---|
| S1 | 소개 + 메시지 폼 | O | QR 링크 | 히어로(손글씨·낙서)·About·Dream·갤러리(9+더보기)·토글 BGM·하단 CTA·바텀시트 폼 |
| S2 | 접수 완료 | - | 제출 성공 후 | 완료 문구 + 후속 연락 안내 |

## 화면 구성
- **S1**: 히어로 → About → Dream → Gallery → 하단 CTA("연아에게 메시지 보내기") → 바텀시트(친구 이름 · 전할 메시지 · 답변받을 연락처 + ⓘ 안내: 전달 방법/보는 사람/답장)
- **S2**: "메시지를 전했어요 · 남겨주신 번호로 연락드릴게요"

## 상태
- 폼: 기본 / 오류(필드별) / 전송 중 / 완료
- 접수 중지 시: 소개만 보이고 폼 제출을 차단한다.
- 이미지 로딩 실패: 폼은 그대로 작동한다.

## 데이터 필드
| 필드 | 필수 | 규칙 |
|---|---|---|
| 친구 이름 | 필수 | 1~30자 |
| 전할 메시지 | 필수 | 1~1,000자 |
| 답변받을 연락처 | 필수 | 휴대폰 번호 |

> ★2(아동 민감정보): 학교·학급·생일·주소 등은 **받지 않는다.**
